## 1. Decisions

| Question | Decision | Why |
|---|---|---|
| Capture | Poll `NSPasteboard.general.changeCount` every 0.5 s with 0.25 s timer tolerance. Always on while the toggle is on, panel open or closed. | macOS has no change event. Reading one integer is microseconds. About 2 wake-ups a second with tolerance coalescing is far below 0.1% CPU. A 1 s poll would miss quick copy-copy sequences. |
| Cost control | Poll is a `Task` loop like the rest of the app (`Task.sleep(for:tolerance:)`). It stops when the toggle is off, and on system or screen sleep; it restarts on wake. Nothing but the integer is read unless it changed. | Zero cost when off or asleep. |
| Storage | **Memory only.** Never written to disk, UserDefaults or the hive. Quitting the app clears it. | Clipboards hold secrets. Disk would keep them past the moment they mattered. Five short-lived items give no reason to persist. |
| Count | Last 5, newest first. | As asked. |
| Re-copy | No duplicate. Same content (SHA-256 of the main data) moves the existing entry to the front. Clicking an entry to copy it back also moves it to the front. Notch ignores its own write (it remembers the `changeCount` after the write). | Otherwise copying back would push a copy of itself in. |
| Toggle | Settings: "Clipboard history", **on by default** (the human asked for the feature). Subtext: "Kept in memory only. Password manager copies are skipped." Turning it off stops polling and clears entries at once. | |
| App pause | Yes, a fixed list, not editable in v1: 1Password, Bitwarden, Dashlane, LastPass, KeePassXC, Enpass, Keychain Access, Passwords (`com.apple.Passwords`). If one of them is the frontmost app when the change is seen, skip it. | Many password managers do not set the concealed flag on every copy. |

## 3. Privacy rules (hard requirements)

1. On a change, read only the type list first. If it contains `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType` or `org.nspasteboard.AutoGeneratedType` (also `com.agilebits.onepassword`, `de.petermaurer.TransientPasteboardType`), record the `changeCount` and stop. The content is never read.
2. Frontmost app in the section 1 list: skip the same way.
3. Memory only. No log lines with content. No network. No hive writes.
4. Toggle off: task cancelled, entries removed.

### macOS 26 "pasteboard access" prompt
What I checked:
- Apple added `NSPasteboard.accessBehavior` in macOS 15.4. The general pasteboard defaults to "ask" when an app reads it without a paste action by the user. The system shows an alert. Apple's docs list it from 15.4: [accessBehavior](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum/default.md).
- Reports disagree on whether macOS 26 enforces it by default. In 15.4 it was a developer preview switch ([report](https://mjtsai.com/blog/2025/05/12/pasteboard-privacy-preview-in-macos-15-4)); a forum thread found no managed setting as of 26 beta 4 ([thread](https://developer.apple.com/forums/thread/794560)).
- This Mac runs 26.5.2. The preview switch `EnablePasteboardPrivacyDeveloperPreview` is not set here.
- No source I found says `changeCount` or the type list trigger the alert. That is unverified.

So this is unknown until tested. Jim's first step is a 10-minute spike on this Mac. **If an alert appears on every poll, stop and tell god: the feature then needs a different approach and a decision from the human.** If it only shows once or never, continue, and at runtime:
- `if #available(macOS 15.4, *)`, read `accessBehavior` (deployment target is 14, so guard it).
- If the setting is "never allow", or data is present but reads come back empty, show one line in the Clipboard view: "Notch can't read the clipboard. Allow it in System Settings → Privacy & Security." Dwight confirms the exact wording of the Settings path on this Mac.
- No new entitlement, no new permission declared by the app.

## 5. Build steps for Jim (about 2.5 h)

Contract: build to `build/` only. No install, no commit, no push. No new dependencies or permissions (CryptoKit and ImageIO are system frameworks). Hive untouched. Tools: Swift, `./build.sh`, the dev Mac's pasteboard. Boundaries: do not touch the audio tap, NowPlaying or the shelf paths storage.

1. Spike (10 min): poll `changeCount` and read types and a string with the app running. Copy from Safari, Terminal and a password manager. Report whether any alert appears. Stop and message god if one appears on every poll.
2. `Sources/Notch/Clipboard.swift` (about 50 min): `@MainActor final class ClipboardHistory: ObservableObject`, owned by `NotchModel` next to `shelf`. `@Published entries: [ClipEntry]` (max 5). `ClipEntry`: id, kind (text, image, file, url), preview string, thumbnail, saved pasteboard items (type → Data, allowed types only), hash, date, source app id.
   - Poll loop as in section 1. Skip rules as in section 3. Caps as in section 2. SHA-256 dedupe moves to front.
   - Thumbnail and hash work off the main thread (utility queue); publish on main.
   - `copyBack(entry)`: write the saved items to the pasteboard, store the new `changeCount` so the poller ignores it, move to front. `remove`, `clear`.
   - Sleep and wake: `NSWorkspace` will-sleep and screens-did-sleep stop the loop, did-wake restarts it.
   - Pure functions for the skip decision and the dedupe, so they can be self-checked.
3. Settings (15 min): `@AppStorage("clipboardHistory")` default true, toggle row. Off: cancel and clear.
4. UI (60 min): the segment switch in the tab row, `ClipboardView` and `ClipCard` per Oscar's spec. Reuse the ShelfItem hover, X and grace logic. Drag out with `onDrag`. Drop on the panel switches to Files.
5. Self-check (15 min): temporary script or debug asserts for the skip rule (concealed, transient, auto-generated, frontmost password app), the dedupe, the cap at 5, and the own-write ignore. Remove or keep as a small test, no framework.
6. Verify (10 min): build with `./build.sh` into `build/`. Idle CPU with the panel closed. Play music and copy 20 times.
